# Diablo IV game data (datamined)

This folder holds structured JSON that was extracted from the locally installed Diablo IV client.
It is generated by `tools/datamine/extract.mjs`. **Do not edit these files by hand.** Re-run the script after a patch instead.

| | |
|---|---|
| Game build | **3.2.2.73764** (`.build.info`: branch `us`, product `fenris`, build key `4e888c791d6c01ad61d258ffa460b661`). Season 15 content is present (`S15_*` strings, `S15_CollectiblePowerCategories`, Hellfire Torch / Annihilus charms) |
| Language | enUS only |
| Type definitions | DiabloTools/d4data `definitions.json` for **3.2.1.73552**. The format hashes for every type parsed here match build 73764. Only `Actor` and `Season` differ, and those are not parsed |
| Generated | see `manifest.json` (`generated`, `counts`, `stringFiles`) |

## Layout

```
data/gamedata/
  manifest.json        build info, counts, per-file stats, parse error count
  strings/*.json       ALL enUS StringLists: { "<stlName>": { "<label>": "<text>" } }
  affixes.json         every Affix (.aff): names, descriptions, attributes, classes, family, tags
  aspects.json         Aspect (.asp) -> affix, name ("of Berserk Ripping"), description, classes
  uniques.json         unique + mythic items with their unique power / forced affixes / flavour
  items.json           index of all named items (sno, id, display name, item type, magic type, classes)
  gems_runes.json      gems (socket effects per slot with resolved text) and runes (ritual / invocation)
  charms.json          talisman charms, seals, blood seals, Season 15 unique charms, and charm set bonuses (2/3/5-piece powers)
  paragon.json         boards (grid of node ids), nodes (attributes), glyphs, glyph affixes, thresholds
  world.json           zones, territories, subzones, worlds, dungeons, level areas, events, dungeon affixes
  monsters.json        named actors (monsters / bosses / NPCs), monster families, monster affixes
  powers.json          skills (Power_* strings with sno) and seasonal powers (CollectiblePower)
  gbid.json            GameBalance name tables (affix families, skill tags, item families, ...)
  raw/                 cache of the binary files copied out of CASC (~110 MB). The app should IGNORE it.
                       Safe to delete. The next full run recreates it. Keep it out of app bundles and VCS.
```

### String files (`strings/`)

The client stores text in about 61.6k StringList files (182.6k strings). They are grouped by name prefix:

| `items.json` | `Item_*`, `ItemType_*`, `SetItemBonus_*`, `RareNameStrings_*`, item labels/slots/tags, `TalismanRarityNames` | 12,335 | 20,276 | 1.6 MB |
| `powers.json` | `Power_*` (skills, passives, legendary powers), `CollectiblePower_*`, `AttributeDescriptions`, skill tags, class mechanics | 2,532 | 12,277 | 1.4 MB |

Example: `strings/items.json` -> `"Item_Gloves_Unique_Generic_002": { "Name": "Fists of Fate", "Flavor": "..." }`.

**Text markup.** Strings contain the game's markup. Strip it for display or OCR matching.
- colour and style tags: `{c_important}…{/c}`, `{c_number}`, `{c_random}`, `{u}…{/u}`, `{icon:bullet,1.2}`
- conditionals: `{if:SF.IsMythic}…{else}…{/if}`
- value placeholders: `[Affix_Value_1*100|1%|]`, `[{VALUE}|~|]`, `{VALUE1}`, `{s1}`, `{SF_2}`, `{payload:…}`

Placeholder format suffixes:
- `|1%|`: one decimal place, then `%`
- `|%x|`: multiplicative percent
- `|~|`: plain number

The structured files add `descPlain` / `textPlain` fields. In these, markup is removed and every unresolved `[...]` value becomes `#`. That suits fuzzy-matching OCR'd tooltip lines such as "+#% Critical Strike Chance".

## Structured file schemas

Every structured file includes `build` and `generated`. Lists live under `entries` (or under the named arrays shown below).
`sno` is the numeric SNO id (stable across patches for existing content). `id` is the internal SNO name.
Classes are `Sorcerer, Druid, Barbarian, Rogue, Necromancer, Spiritborn, Paladin, Warlock`. `["All"]` means usable by every class.

### `affixes.json` → `entries[]`
```jsonc
{
  "sno": 578706, "id": "legendary_barb_001",
  "name": "of Berserk Ripping",            // legendary/unique affixes: display name (aspect name)
  "namePrefix": "Swift", "nameSuffix": "of Swiftness",   // regular affixes: rare-name fragments
  "desc": "While {c_important}…[Affix_Value_1*100|%|]…[Affix.\"Static Value 0\"]…",  // raw
  "descResolved": "… over {c_number}5{/c} seconds.",   // static values substituted (when present)
  "descPlain": "While Berserking, your direct damage inflicts # bonus Bleeding damage over 5 seconds.",
  "magicType": 1,        // 0 = regular/magic stat affix, 1 = legendary (aspect), 2 = unique power, 4 = mythic, 3 = other (raw enum)
  "affixType": 1,        // raw enum (1 = power/legendary, 2 = stat affix, 0 = inherent/implicit)
  "category": 0, "itemPower": [391, 2000], "classes": ["Barbarian"],
  "family": "Legendary",                    // GameBalance AffixFamilyList name
  "itemLabels": [0, 28, 26, 19],            // raw item-label enum values (allowed slots)
  "attributes": [{                           // what the affix grants
     "attribute": "Power_Cooldown_Reduction_Percent_All",
     "param": 1879127, "paramName": "Druid_Tectonic", "paramDisplayName": "Tectonic Spikes",
     "formula": "0.39+CurrentLegendaryRank()*0.01",   // inline formula (if any)
     "formulaTable": "AffixPercentage0.5x",           // GameBalance AttributeFormulas table (if any)
     "value": 5,                                      // only when the formula is a constant
     "text": "[{VALUE1}*100|1%|] Cooldown Reduction", // AttributeDescriptions tooltip line
     "textPlain": "# Cooldown Reduction", "textResolved": "5 Strength" }],
  "staticValues": [5], "maxLegendaryRanks": [16,13,21,16,0,0],
  "passivePower": { "sno": 340795, "id": "legendary_barb_001" },
  "skillTags": ["FILTER_Legendary_…"], "affixTags": [], "itemTags": [], "tempered": false, "sealTag": null,
  "strings": { "CodexDesc": "…" }           // any other labels from the Affix_<id> StringList
}
```
Item affix values roll from `formulaTable` curves (server-side/GameBalance formula tables) and the item power, so most stat affixes keep a `#` placeholder. Legendary values use `formula` with `CurrentLegendaryRank()`.

### `aspects.json` → `entries[]`
`{ sno, id: "Asp_Legendary_Barb_041", name: "of Ancestral Force", affix: {sno, id}, desc, descResolved, descPlain, classes, category, attributes, staticValues, maxLegendaryRanks }`

### `uniques.json` → `entries[]`
`{ sno, id, name, flavor, itemType, itemTypeName, magicType (2 unique | 4 mythic), mythic: bool, seasonVariant: "S14"?, classes, baseItem: {sno,id}, uniquePower: {sno,id,desc,descPlain,…}, forcedAffixes: [affixBrief], inherentAffixes: [affixBrief], charmVersion: [{sno,id}], strings }`.
`affixBrief` = `{ sno, id, name?, namePrefix?, nameSuffix?, desc?, descResolved?, descPlain?, attributeText?[] }`.
The same unique can appear several times, for example as a seasonal `S14_*` copy or a "(Crucible)" variant. 870 entries cover 452 distinct names, and 19 entries are mythic.

### `items.json`
`{ itemTypes: { "<ItemType id>": "<display name>" }, entries: [{ sno, id, name, itemType, itemTypeName, magicType, classes, seasonItem, placeholder? }] }`.
It contains every item that has an enUS name (12k, including quest items, cosmetics and consumables).

### `gems_runes.json`
- `gems[]`: `{ sno, id, name, flavor, socketedEffects: [{ target: "weapon"|"armor"|"jewelry", attributes: [attr…] }], forcedAffix }`. For example, a Crude Ruby gives `x5% Fire and Holy Damage Multiplier` in a weapon, `5 Strength` in armor, and `+20 {VALUE1} Resistance` in jewelry. In that last line `param` 1 is the damage-type enum (fire).
- `runes[]`: `{ sno, id, name: "Cem", kind: "ritual"|"invocation", runeDescription, runeDescriptionPlain, runewordPrefix, rarity, runicPower, power }`

### `charms.json`
- `charms[]`: items named `Talisman*` / `*Charm*` / `*Seal*`, or with a charm rarity. Each entry is `{ sno, id, name, charmRarity, classes, setBonus, setBonusName, forcedAffixes, inherentAffixes, strings }`. This covers set charms, unique charms (`Talisman_Charm_Unique_*`, `S15_Charm_Unique_*`), seals (`Talisman_Seal_*`) and blood seals.
- `setBonuses[]`: `{ sno, id, name: "Habacalva's Cauldron", classHint, tiers: [{ pieces: 2|3|5, affix: affixBrief }] }`. The tier descriptions are fully resolved, for example "…increasing your Pyromancy damage by 7%, stacking up to 15 times…".

### `paragon.json`
- `boards[]`: `{ sno, id: "Paragon_Barb_02", name: "Blood Rage", classHint, width, height, grid: [[nodeId|null,…],…], nodeSnos }`. There are 10 boards per class.
- `nodes[]`: `{ sno, id, name, desc, rarity (0 normal/start/gate/socket, 2 magic, 3 rare, 4 legendary), gate, socket, attributes: [attr…], bonusAttributeIndices, thresholds, passivePower, skillTags }`
- `glyphs[]`: `{ sno, id, name: "Enchanter", rarity, classes, affixes: [{sno, id, desc}] }`
- `glyphAffixes[]`: `{ sno, id, desc, descPlain, data }`. `{GlyphAffixScalar}` scales with glyph level.
- `thresholds[]`: raw ParagonThreshold data

### `world.json`
`zones[]`, `territories[]`, `subzones[]`, `worlds[]` (`dungeon: true` for `DGN_*`), `dungeons[]` (164), and `levelAreas[]` share the shape `{ sno, id, name, desc? }`.
`events[]`: `{ sno, id, name, type }`, where `type` is `world_boss`, `legion`, `helltide`, `world_event`, `dynamic_event`, `local_event`, `bounty` or `zone_event`. The world bosses are Ashava, Avarice, Wandering Death, Azmodan, Chi'Khan and Moophisto.
`dungeonAffixes[]`, `communityModifiers[]` and `worldStates[]` are also included.

### `monsters.json`
- `actors[]`: `{ sno, id, name, flavorName?, boss?, worldBoss? }`. This is every actor with an enUS name. `boss` is set when the internal id contains "boss", which includes minibosses and boss adds.
- `bosses[]` is the `boss` / `worldBoss` subset.
- `monsterFamilies[]`, `monsterAffixes[]` (elite affixes), and `monsterNameTable` (GameBalance MonsterNames ids).

### `powers.json`
`skills[]` holds `{ sno, id: "Barbarian_Bash", name, desc, strings }`. These descriptions contain script placeholders (`{SF_2}`, `{payload:…}`) that cannot be resolved offline. `seasonalPowers[]` holds CollectiblePower entries.

## What is NOT here (and why)

- **Treasure classes / boss loot tables.** The client's CoreTOC has no `TreasureClass` SNO group. Item files only reference treasure-class SNO ids, which have no name. Drop tables are server-side, so boss farm targets must come from community sources.
- **Exact affix roll ranges.** Stat affixes reference GameBalance formula tables (`formulaTable`) that are evaluated against item power on the server. Inline legendary formulas (`formula`) are exported as text.
- **Encrypted content.** 962 of the 35,159 requested meta files and 170 `StringList-Text-enUS-0x….dat` blocks are encrypted with TACT keys that are not distributed, which usually means unreleased content. The client lists 11,698 encrypted SNOs in total. These entries appear without parsed data (`encrypted: true` where applicable). The old key source (`d4armory.io/api/keys`, used by d4data) no longer works.
- **Skill numbers.** Skill damage values live in Power payload scripts and are not parsed.

## How to re-run after a patch

Prerequisites: Node 22+ and Git. Building `cascx.exe` also needs mingw-w64 `gcc`/`g++` on PATH; it is built automatically if missing. `curl` is used to fetch d4data definitions.

```powershell
# from the repo root; the game may be closed or running (all access is read-only)
node tools/datamine/extract.mjs                       # full run: copy from CASC + parse (~1 min)
node tools/datamine/extract.mjs --update-defs         # also refresh d4data definitions.json (do this after a patch)
node tools/datamine/extract.mjs --skip-casc           # re-parse the existing raw/ cache only (~10 s)
node tools/datamine/extract.mjs --game "D:\Games\Diablo IV"   # or set D4_GAME_DIR
```

After a patch:
1. Run with `--update-defs` (DiabloTools/d4data usually publishes new definitions within days of a patch).
2. Check `manifest.json`. `parseErrors` should be 0. If a file fails to parse, the error goes to `parse-errors.txt`. That usually means `definitions.json` is older than the game build, so wait for d4data to update and re-run.
3. If CascLib fails to open the storage after a client format change, delete `tools/vendor/CascLib` and `tools/datamine/bin/cascx.exe` and re-run. The script then clones the latest CascLib and rebuilds.

## Tools used

- **CascLib** (ladislav-zezula/CascLib, master 2026-09-25, `38a3466`, MIT) is compiled into `tools/datamine/bin/cascx.exe`. The source is `tools/datamine/cascx/cascx.cpp`. It is a small read-only extractor. Every `CreateFile` that CascLib makes is routed through a wrapper. The wrapper strips write access, adds full share flags (so the game or launcher is never locked out) and refuses any non-`OPEN_EXISTING` disposition. `CreateDirectory` and `MoveFileEx` are stubbed out. Nothing under the game directory can be created, modified or write-locked.
  - commands: `cascx <game> info | list <mask…> | extract <outDir> <mask…> | extract-list <outDir> <listFile>`
  - storage paths look like `base:CoreTOC.dat`, `base:StringList-Text-enUS.dat` and `base:meta\<snoId>`. Meta files are named by SNO id, and `CoreTOC.dat` maps ids to group and name.
- **DiabloTools/d4data** (MIT) supplies `definitions.json`, `attributeList.json` and `json/snoFileInfo.json`, kept in `tools/vendor/d4data/`. `tools/datamine/lib/d4meta.mjs` is a port of its `parse.js` binary reader with a simpler output shape.
- `tools/datamine/extract.mjs` is the end-to-end pipeline.

Format notes:
- enUS strings come in one combined container, `base:StringList-Text-enUS.dat` (signature `0x44CF00F5`). It holds 61,584 StringList SNOs, each a `StringListDefinition { arStrings: [{szLabel, szText, hLabel}] }`.
- Other meta files are standalone. Each has a `0xDEADBEEF` header plus a format hash, and its type comes from `definitions.json`.
- GBID references are resolved by building `djb2(lowercase(name))` tables from every GameBalance file.
